# «Аким на 5 часов» — AI-симулятор управления городом

Кейс HackAlem AI. Команда получает виртуальный бюджет 100 ед. и данные по пяти условным районам Астаны,
принимает ровно 5 управленческих решений по пяти направлениям (транспорт, экология, соцсфера, безопасность,
сервисы) и получает **Astana Quality of Life Score** с объяснением, критикой, рекомендациями и стресс-тестом
«Чёрный лебедь».

> Ключевой принцип: **все числа считает детерминированный движок, LLM их только объясняет.**
> Модель получает готовую трассу расчёта (дельты по районам и показателям, вклад каждой меры, синергии,
> разрыв до оптимума) и работает поверх неё. Каждая рекомендация советника перепроверяется движком перед выводом.

## Что умеет

| Must have из ТЗ | Как реализовано |
|---|---|
| Единый бюджет и датасет для всех | `data/*.json` — единственный источник правды, загружается при старте |
| 5 решений по 5 направлениям | Каталог 14 мер, слоты решений, выбор района для мер типа «Район» |
| Контроль превышения бюджета | Живая валидация при каждом клике (`POST /api/validate`), кнопка расчёта недоступна для невалидного набора; сервер отвергает невалидный набор с кодом 422 |
| AI-анализ решений | Три агента: **Аналитик** (объяснение), **Критик** (аудит слабых мест), **Советник** (агентный цикл с tool-calling к движку) |
| Расчёт Score | Формула из датасета 1:1, полная трасса, тесты на контрольные числа (база 52.56, пример 56.54) |
| Сильные стороны, риски, последствия | Карточки Аналитика/Критика + «голос жителя» самого слабого района |

| Опционально из ТЗ | Как реализовано |
|---|---|
| Сравнение результатов команд | SQLite-лидерборд, side-by-side сравнение любых двух сценариев (`POST /api/compare`) |
| Визуализация изменений районов | Бары «до/после», радар по направлениям, тепловая карта 5×10 с дельтами и критическими ячейками, водопад вклада мер |
| AI-рекомендации по улучшению | **Оракул**: полный перебор всех ~694 тыс. допустимых наборов (numpy, ~1 с) → глобальный максимум, перцентиль сценария, Парето «стоимость→Score», лучшие одиночные замены с кнопкой «Применить» |
| Неожиданные события | 6 событий «Чёрный лебедь»: шоки показателей, блокировка мер, секвестр бюджета; план пересчитывается в новом мире, LLM пишет сводку |
| Автогенерация презентации | Одностраничный HTML-отчёт по сценарию (`GET /api/report/{id}`), печатается в PDF |

Плюс **Совет депутатов**: 4 LLM-персоны (эколог, транспортник, финансист, депутат от Нуры) оценивают сценарий
с разных позиций, модератор подводит итог — наглядная демонстрация компромиссов.

## Быстрый старт

### Вариант A — Docker (одна команда)

```bash
cp .env.example .env        # необязательно: впишите ключ LLM
docker compose up --build   # → http://localhost:8000
```

### Вариант B — локально (Python 3.11+, Node 20+)

```bash
# бэкенд
pip install -r backend/requirements.txt
cd backend && uvicorn app.main:app --reload --port 8000

# фронтенд (в другом терминале)
cd frontend && npm install && npm run dev      # → http://localhost:5173 (проксирует /api на :8000)
```

Либо собрать фронт один раз (`cd frontend && npm run build`) — тогда FastAPI сам раздаёт `frontend/dist`
на http://localhost:8000.

### Тесты

```bash
cd backend && python -m pytest -q      # 20 тестов: формула, валидатор, оракул, события, API
```

### Подключение LLM

Без ключа всё работает в **шаблонном режиме** (объяснения генерируются детерминированно из трассы) — это видно
по бейджу в шапке. Чтобы включить LLM, задайте переменные окружения (см. `.env.example`):

```bash
# OpenAI
LLM_PROVIDER=openai  LLM_API_KEY=sk-...  LLM_MODEL=gpt-4o-mini
# NVIDIA NIM (OpenAI-совместимый)
LLM_PROVIDER=nvidia  LLM_API_KEY=nvapi-...  LLM_MODEL=meta/llama-3.1-70b-instruct
```

Любой OpenAI-совместимый сервер подключается через `LLM_PROVIDER=custom` + `LLM_BASE_URL`.
Если запрос к модели упал, агент автоматически деградирует в шаблонный режим и помечает ответ `_mode: fallback`.

## Сценарий работы

1. **Решения.** Выберите 5 мер в каталоге (для «районных» — укажите район). Справа — слоты, полоса бюджета,
   счётчик по направлениям и живой список нарушений правил. Кнопка расчёта активна только для валидного набора.
2. **Результат и AI.** KPI (Score, дельта к базе, средний и минимальный балл районов, штраф за критические
   значения, перцентиль среди всех допустимых наборов), графики, тепловая карта. Ниже — Аналитик, Критик и
   Советник; рекомендации советника применяются одним кликом.
3. **Совет.** Созовите Совет депутатов — четыре точки зрения и вердикт модератора.
4. **Событие.** Запустите случайное или выбранное событие: увидите шок по показателям, блокировки, новый бюджет,
   насколько «просел» план и валиден ли он. «Перепланировать в этом мире» переключает весь симулятор в мир после
   события (шапка показывает активное событие).
5. **Лидерборд.** Отправьте сценарий под именем команды, сравните любые два сценария, откройте отчёт-презентацию.
   Справа — гистограмма всех допустимых наборов от оракула с отметкой вашего результата.

```
│  ├─ districts.json          # районы, показатели, веса, правила
│  ├─ measures.json           # 14 мер, синергии, несовместимости
│  └─ events.json             # события «Чёрный лебедь»
├─ backend/
│  ├─ app/engine/             # ДЕТЕРМИНИРОВАННЫЙ ДВИЖОК (без LLM)
│  │  ├─ data.py              #   загрузка датасета
│  │  ├─ validator.py         #   8 правил + блокировки событий → список причин
│  │  ├─ scorer.py            #   формула Score, полная трасса, маржинальный вклад мер
│  │  ├─ optimizer.py         #   оракул: numpy-перебор всех наборов, Парето, перцентиль, best_swaps
│  │  └─ events.py            #   применение события → новое состояние мира
│  ├─ app/ai/                 # LLM-СЛОЙ (поверх трассы движка)
│  │  ├─ llm.py               #   OpenAI-совместимый клиент, JSON-режим, агентный цикл с tools
│  │  ├─ context.py           #   компактный контекст для промптов из ScoreResult + оракула
│  │  ├─ agents.py            #   промпты и схемы: Аналитик, Критик, Советник(tools), Совет, Рассказчик
│  │  ├─ fallback.py          #   те же ответы без LLM (шаблоны по трассе)
│  │  └─ pipeline.py          #   параллельный запуск, деградация в fallback
│  ├─ app/db.py               # SQLite-лидерборд
│  ├─ app/report.py           # HTML-презентация сценария
│  ├─ app/main.py             # FastAPI, раздача собранного фронта
│  └─ tests/                  # pytest: движок + API
├─ frontend/                  # React 19 + TypeScript + Vite + Recharts
│  └─ src/components/         # Planner, Results, AIPanel, CouncilPanel, EventPanel, Leaderboard
├─ Dockerfile, docker-compose.yml, Makefile, .env.example
```

### Поток данных

```
UI ──decisions──▶ validator ──ok──▶ scorer ──ScoreResult(трасса)──▶ context ──▶ [Analyst | Critic | Advisor]
                                        │                                              │        ▲
                                        └──▶ optimizer (оракул, best_swaps) ───────────┘        │ tools:
                                                                                 score_scenario / best_swaps / oracle_best
```

Советник работает как агент: модель вызывает инструменты движка (`score_scenario`, `best_swaps`, `oracle_best`),
получает посчитанные результаты и формирует рекомендации; сервер затем **повторно валидирует и пересчитывает** каждую
рекомендацию, помечая `verified: true/false`, — выдуманный Score в UI попасть не может.

### Движок: формула и правила

Реализовано строго по датасету:

- `I'_dk = clip(I_dk + Σ effect_m,k × (8 − L_m)/8 + synergy, 0, 100)` — лаг масштабирует эффект, синергия — нет;
- бонус синергии для пары «районных» мер идёт в район первой меры пары (для M10+M12 — в район M10);
- `D_d = Σ w_k I'_dk`, `D_avg = Σ pop_d D_d`, `Score = 0.7·D_avg + 0.3·min(D_d) − 1.0·N_crit`, `N_crit` — число ячеек `< 40`;
- правила: бюджет 100, ровно 5 решений, без повторов, район обязателен для «Район» и запрещён для «Город»,
  не более 2 мер на направление, несовместимости M1/M3 (везде), M4+M7 и M5+M13 (в одном районе).

Контрольные числа воспроизводятся тестами: база **52.56** (2 критических: S1, S2 в Нуре), пример из датасета —
**56.54** (+3.99, синергия M10+M12). Полный перебор даёт **694 395** допустимых наборов, глобальный максимум
**57.24** (M2 · M3 Нура · M8 Нура · M9 Нура · M14, стоимость 98).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta` | датасет, правила, события, статус LLM |
| POST | `/api/validate` | проверка набора → список нарушений |
| POST | `/api/score` | валидация + полная трасса Score (422 не бросает: `result=null` при ошибках) |
| POST | `/api/analyze` | Аналитик + Критик + Советник + оракул |
| POST | `/api/council` | Совет депутатов |
| GET | `/api/oracle?event_id=` | лучший набор, топ-10, Парето, гистограмма |
| POST | `/api/oracle/position` | перцентиль и лучшие замены для набора |
| GET | `/api/events` | каталог событий |
| POST | `/api/event/trigger` | применить событие к плану команды (+ нарратив) |
| GET/POST | `/api/leaderboard` | лидерборд / отправка сценария |
| POST | `/api/compare` | сравнение двух сценариев |
| GET | `/api/report/{id}` | HTML-презентация сценария |

Тело запросов: `{"decisions":[{"measure_id":"M7","district_id":"nura"}, {"measure_id":"M12"}], "event_id": null}`.
Swagger: http://localhost:8000/docs.

## Потенциал развития

- Подключение реальных открытых данных Астаны вместо синтетики (структура `data/*.json` уже под это готова).
- Многопользовательский режим в реальном времени и турнир команд по серии событий.
- Обучение весов и эффектов мер на исторических данных; калибровка лагов.
- Расширение агентов: «эксперт по закупкам» с оценкой реализуемости, генерация дорожной карты по кварталам.
