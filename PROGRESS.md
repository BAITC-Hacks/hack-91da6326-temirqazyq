## Правила продолжения
- Не выводить ключ и не переписывать пользовательский .env.
- Не выполнять live-вызовы до офлайн-тестов. Лимит live-проверки общий для всей доработки.
- Не оставлять запущенные тестовые серверы; пользователь запускает собственные процессы.
- Не останавливать пользовательские процессы и не запускать npm ci поверх работающего frontend.
- Root: orchestration/API/интеграция/документация. engine: storage/contracts/tools/math. optimizer: provider/settings/usage. frontend: UI/tests.
- Live-попыток выполнено: **8 из 8**. Оценка по фактическому usage: **$0.0109676**. Дальнейшие live-вызовы в рамках этой доработки запрещены лимитом задания.

- Обычный pytest блокирует внешний HTTP transport и отключает AI независимо от пользовательского .env.
- Провайдер и ledger: 29 mock-тестов, включая параллельное резервирование, unknown usage, cancel и повторные попытки.
- Полный HTTP smoke через Next.js на отдельных портах 3011/8011 прошёл: preview/final, 3 алгоритмических варианта, compare, session, save/load/export; платных вызовов 0. Оба тестовых сервера остановлены; сервер пользователя на 8000 не затрагивался.

## Исправление ошибки пользователя: ссылки critical_after
- Прочитаны доступный `frontend/.next/dev/logs/next-development.log` и сохранённые ошибки/журнал инструментов в `var/akim.sqlite3` (только чтение). Обнаружены сообщённая ошибка A/B/C.critical_after и отдельное отклонение числовых литералов в объяснении. Предупреждения Next.js/Recharts о размере графиков не являются причиной ошибки проверки ссылок.
- Причина: модель ссылалась на существующие списки критических показателей, но карта разрешённых фактов содержала только их `.count` и отдельные значения. Зарегистрированы сами коллекции critical_before/critical_after/activated_synergies, включая пустые списки. Список и его количество остаются разными фактами; коллекции нельзя подставлять вместо числа.
- Уточнён промпт, изменена версия кеша на v2.5. При ошибке grounding добавлена одна корректирующая попытка объяснения внутри прежних лимитов вызовов, стоимости и времени; отказ/неполный ответ не повторяются. Кешируется только проверенный результат, число исправлений объяснения отражено в metadata.
- На сохранённых данных конкретного неудачного запуска проверка трёх ссылок прошла; в каждом списке действительно по одному критическому показателю. Это офлайн-регрессия, а не восстановление утраченного исходного текста модели.
- Добавлены 25 регрессий коллекций и 9 проверок исправления объяснения, все прошли. Полный backend suite: **289 passed** за 25.36 сек., одно прежнее предупреждение Starlette/httpx.
- Новых платных API-вызовов не выполнялось, .env не изменён, пользовательские серверы не останавливались.

## Исправление ошибки пользователя: NO_VERIFIED_CANDIDATES
- Прочитан последний неудачный запуск `4c4db183a8e4b1e7e4360842c5a3aa67` и кеш отклонённых черновиков его сессии, без записи в пользовательскую БД. Запрос «нужно сохранить 30 единиц бюджета» сохранил предыдущий max_budget=90, исключение M3 и анализ S1/S2 в Нуре; эффективный бюджет равен 70. В кеше ошибки USER_BUDGET_EXCEEDED и CATEGORY_LIMIT (social); в прежнем журнале инструментов вложенные причины не сохранялись.
- Исправлен промпт генерации: учитывать каталог стоимости при планировании, точный доступный расход после резерва, отличать показатели для анализа от обязательных мер. Числа модели по-прежнему не принимаются как результаты. Для каждого отклонённого черновика Python возвращает стоимость, лимит, превышение, стоимость мер и распределение по категориям; неизвестная мера не получает выдуманную цену.
- Отклонённые черновики из старого кеша повторно валидируются. В журнале сохраняются вложенные коды ошибок и различаются полностью отклонённые и смешанные пакеты. Причины видны в этапах исправления и итоговом сообщении NO_VERIFIED_CANDIDATES. Лимиты запросов и ограничения пользователя не увеличены и не ослаблены.
- Добавлены офлайн-регрессии: уточнение reserve=30, исправление стоимости 80 до трёх допустимых наборов 70/66/61, исчерпание попыток без выдуманных результатов. Оптимизатор при AI-генерации не вызывается. Это сценарии с замоканным ответом провайдера, не подтверждение качества нового ответа облачной модели.
- Закрыт обход актуальных ограничений через модельный compare_scenarios: старые сценарии повторно проверяются по текущему бюджету, исключениям и зафиксированным мерам до принятия в генерацию. Явное сравнение исторических сценариев пользователем остаётся отдельной операцией.
- Добавлены 12 проверок обратной связи валидатора и 3 регрессии генерации. Полный backend suite: **304 passed** за 32.77 сек., одно прежнее предупреждение Starlette/httpx; команда `.\.venv\Scripts\python.exe -X utf8 -m pytest backend/tests -q -o addopts=''`.
- Офлайн-проверка размера запросов с тремя плохими кандидатами в каждом из трёх раундов: максимальная оценка входа 6202 токена при лимите 12000 (включая схемы и накладные расходы). Новый feedback помещается в прежний лимит контекста.
- Новых платных API-вызовов не выполнялось; .env и пользовательские процессы не менялись. После обновления нужен перезапуск backend и новая операция в интерфейсе; сохранённая неудачная операция остаётся в истории.

## Графики и технические ошибки в интерфейсе
- Предупреждения Recharts width(0)/height(0) возникают при измерении скрытых контейнеров. ResponsiveContainer заменён общим MeasuredChart: SVG монтируется только при положительных фактических размерах, ResizeObserver отслеживает показ/скрытие и изменение размера. Для печати размеры обновляются синхронно, анимация графиков отключена. CSS-контейнер сохраняется, поэтому скрытая вкладка может корректно восстановить график.
- Технические сообщения исключены из уведомлений, статусов, этапов и истории UI. Неудачная операция имеет один короткий статус и следующий шаг. Полезные подсказки по выбору мер сохраняются, но формируются из локальных текстов интерфейса без внутренних кодов. HTTP/network errors не передают в уведомления исходный response/error.message.
- Backend записывает диагностику в терминал с кодом и run_id; ключи, Bearer-токены, управляющие символы и исходные ответы провайдера не логируются. Неожиданные исключения логируются по типу и расположению кадров без текста исключения/локальных переменных. API выдаёт безопасную копию статуса, а SQLite сохраняет причины для диагностики. Старые ошибки очищаются при чтении истории без изменения исходных записей; новые получают kind=error.
- Исправлена отдельная причина ошибки на скриншоте: добавлены реальные scalar-факты элементов critical_before/after и activated_synergies, поддержана безопасная нормализация [0] в .0 и разбор вложенных скобок в placeholder. Подстановка разрешена только для точного существующего ключа, выдуманные индексы/поля отклоняются. Версия кеша объяснений v2.6.
- Проверки: **350 backend tests passed** (33.96 сек.), **23 UI tests passed**, **8 frontend API tests passed**, TypeScript и production build прошли. Среди новых тестов: 9 для размеров/скрытых вкладок/SSR/печати, 31 для индексированных ссылок, 15 для безопасного публичного вывода и терминальных логов. Recharts в регрессионных тестах настоящий; jsdom подставляет только размеры DOM.
- Сборка выполнена отдельно в .next-smoke, добавленные Next.js временные ссылки в tsconfig/next-env возвращены к обычному .next. Остались прежнее предупреждение Starlette/httpx и предупреждение Next.js о package-lock за пределами репозитория. Управляемый браузер недоступен (нет browsers; IAB сообщает Browser is not available), поэтому визуальная проверка и реальная печать не подтверждены.
- Платные API-вызовы не выполнялись, .env не менялся, пользовательские процессы не останавливались. Нужны перезапуск backend и обновление страницы; для запуска из production-сборки также пересобрать frontend.
