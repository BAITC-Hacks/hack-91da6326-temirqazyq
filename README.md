# «Аким на 5 часов» — AI-симулятор управления городом

Кейс HackAlem AI. Команда получает виртуальный бюджет 100 ед. и данные по пяти условным районам Астаны,
принимает ровно 5 управленческих решений по пяти направлениям (транспорт, экология, соцсфера, безопасность,
сервисы) и получает **Astana Quality of Life Score** с объяснением, критикой, рекомендациями и стресс-тестом
«Чёрный лебедь».

> Ключевой принцип: **все числа считает детерминированный движок, LLM их только объясняет.**
> Модель получает готовую трассу расчёта (дельты по районам и показателям, вклад каждой меры, синергии,
> разрыв до оптимума) и работает поверх неё. Каждая рекомендация советника перепроверяется движком перед выводом.

## Что умеет

| Must have из ТЗ | Как реализовано |
|---|---|
| Единый бюджет и датасет для всех | `data/*.json` — единственный источник правды, загружается при старте |
| 5 решений по 5 направлениям | Каталог 14 мер, слоты решений, выбор района для мер типа «Район» |
| Контроль превышения бюджета | Живая валидация при каждом клике (`POST /api/validate`), кнопка расчёта недоступна для невалидного набора; сервер отвергает невалидный набор с кодом 422 |
| AI-анализ решений | Три агента: **Аналитик** (объяснение), **Критик** (аудит слабых мест), **Советник** (агентный цикл с tool-calling к движку) |
| Расчёт Score | Формула из датасета 1:1, полная трасса, тесты на контрольные числа (база 52.56, пример 56.54) |
| Сильные стороны, риски, последствия | Карточки Аналитика/Критика + «голос жителя» самого слабого района |

| Опционально из ТЗ | Как реализовано |
|---|---|
| Сравнение результатов команд | SQLite-лидерборд, side-by-side сравнение любых двух сценариев (`POST /api/compare`) |
| Визуализация изменений районов | Dumbbell «до → после» по районам и направлениям, диверегирующие бары вклада каждой меры, тепловая карта 5×10 со шкалой и расшифровкой кодов |
| AI-рекомендации по улучшению | **Оракул**: полный перебор всех ~694 тыс. допустимых наборов (numpy, ~1 с) → глобальный максимум, перцентиль сценария, Парето «стоимость→Score», лучшие одиночные замены с кнопкой «Применить» |
| Неожиданные события | 6 готовых событий «Чёрный лебедь» **плюс своя проблема произвольным текстом**: LLM переводит описание в шоки показателей, блокировки и секвестр, движок считает последствия и подбирает лучший набор уже в новом мире |
| Автогенерация презентации | Одностраничный HTML-отчёт по сценарию (`GET /api/report/{id}`), печатается в PDF |

Плюс **Совет депутатов**: 4 LLM-персоны (эколог, транспортник, финансист, депутат от Нуры) оценивают сценарий
с разных позиций, модератор подводит итог — наглядная демонстрация компромиссов.

## Быстрый старт

### Вариант A — Docker (одна команда)

```bash
cp .env.example .env        # необязательно: впишите ключ LLM
docker compose up --build   # → http://localhost:8000
```

### Вариант B — локально (Python 3.11+, Node 20+)

```bash
# бэкенд
pip install -r backend/requirements.txt
cd backend && uvicorn app.main:app --reload --port 8000

# фронтенд (в другом терминале)
cd frontend && npm install && npm run dev      # → http://localhost:5173 (проксирует /api на :8000)
```

Либо собрать фронт один раз (`cd frontend && npm run build`) — тогда FastAPI сам раздаёт `frontend/dist`
на http://localhost:8000.

### Тесты

```bash
cd backend && python -m pytest -q      # 24 теста: формула, валидатор, оракул, события, санитайзер, API
```

### Подключение LLM

Без ключа всё работает в **шаблонном режиме** (объяснения генерируются детерминированно из трассы) — это видно
по бейджу в шапке. Чтобы включить LLM, задайте переменные окружения (см. `.env.example`):

```bash
# OpenAI
LLM_PROVIDER=openai  LLM_API_KEY=sk-...  LLM_MODEL=gpt-4o-mini
# NVIDIA NIM (build.nvidia.com) — base_url подставит пресет, хватает двух строк
LLM_PROVIDER=nvidia  LLM_API_KEY=nvapi-...
```

Любой OpenAI-совместимый сервер подключается через `LLM_PROVIDER=custom` + `LLM_BASE_URL`.

Про NVIDIA отдельно: Советник работает через tool-calling, и его поддерживают не все модели каталога.
Если выбранная модель не умеет вызывать инструменты, этот агент уйдёт в шаблонный режим и пометит ответ
`_mode: fallback` — остальные три агента и весь движок при этом работают как обычно.
Если запрос к модели упал, агент автоматически деградирует в шаблонный режим и помечает ответ `_mode: fallback`.

## Сценарий работы

0. **Первый запуск.** Короткое вступление объясняет, что за игра, какая цель и между какими ориентирами
   идёт борьба: ничего не делать — 52.56, лучший возможный план — 57.24. Показывается один раз, вернуть можно
   кнопкой «?» в шапке.
1. **Решения.** Выберите 5 мер в каталоге (для «районных» — укажите район). Справа — слоты, полоса бюджета,
   счётчик по направлениям и живой список нарушений правил. Кнопка расчёта активна только для валидного набора.
2. **Результат и AI.** KPI (Score, дельта к базе, средний и минимальный балл районов, штраф за критические
   значения, перцентиль среди всех допустимых наборов), графики, тепловая карта. Ниже — Аналитик, Критик и
   Советник; рекомендации советника применяются одним кликом.
3. **Совет.** Созовите Совет депутатов — четыре точки зрения и вердикт модератора.
4. **Событие.** Запустите случайное или выбранное событие: увидите шок по показателям, блокировки, новый бюджет,
   насколько «просел» план и валиден ли он. «Перепланировать в этом мире» переключает весь симулятор в мир после
   события (шапка показывает активное событие).
5. **Лидерборд.** Отправьте сценарий под именем команды, сравните любые два сценария, откройте отчёт-презентацию.
   Справа — гистограмма всех допустимых наборов от оракула с отметкой вашего результата.

### Поток данных

```
UI ──decisions──▶ validator ──ok──▶ scorer ──ScoreResult(трасса)──▶ context ──▶ [Analyst | Critic | Advisor]
                                        │                                              │        ▲
                                        └──▶ optimizer (оракул, best_swaps) ───────────┘        │ tools:
                                                                                 score_scenario / best_swaps / oracle_best
```

Советник работает как агент: модель вызывает инструменты движка (`score_scenario`, `best_swaps`, `oracle_best`),
получает посчитанные результаты и формирует рекомендации; сервер затем **повторно валидирует и пересчитывает** каждую
рекомендацию, помечая `verified: true/false`, — выдуманный Score в UI попасть не может.

### Движок: формула и правила

Реализовано строго по датасету:

- `I'_dk = clip(I_dk + Σ effect_m,k × (8 − L_m)/8 + synergy, 0, 100)` — лаг масштабирует эффект, синергия — нет;
- бонус синергии для пары «районных» мер идёт в район первой меры пары (для M10+M12 — в район M10);
- `D_d = Σ w_k I'_dk`, `D_avg = Σ pop_d D_d`, `Score = 0.7·D_avg + 0.3·min(D_d) − 1.0·N_crit`, `N_crit` — число ячеек `< 40`;
- правила: бюджет 100, ровно 5 решений, без повторов, район обязателен для «Район» и запрещён для «Город»,
  не более 2 мер на направление, несовместимости M1/M3 (везде), M4+M7 и M5+M13 (в одном районе).

Контрольные числа воспроизводятся тестами: база **52.56** (2 критических: S1, S2 в Нуре), пример из датасета —
**56.54** (+3.98, синергия M10+M12). Полный перебор даёт **694 395** допустимых наборов, глобальный максимум
**57.24** (M2 · M3 Нура · M8 Нура · M9 Нура · M14, стоимость 98).

### Как делится прирост между мерами

Простая разность «Score с мерой минус Score без неё» **не аддитивна**: бонус синергии M10+M12 засчитывается
и в M10, и в M12, поэтому сумма таких вкладов (4.06) расходится с общим приростом (3.98). Поэтому вклад
считается **вектором Шепли** — усреднением по всем порядкам добавления мер (`shapley_contributions()` в
`scorer.py`, 2⁵ = 32 расчёта, доли миллисекунды). Сумма вкладов равна приросту с машинной точностью;
это проверяется тестом `test_shapley_sums_exactly_to_delta`.

Маржинальный вклад никуда не делся — он остался в трассе и показывается в подсказке строки («если просто
убрать эту меру»). Разница между двумя числами и есть эффект пересечения с остальными мерами.

Округления согласованы: `delta` считается как разность **округлённых** значений, иначе на экране
`56.54 − 52.56` давало бы 3.98, а подписано было бы 3.99. Точные значения лежат в `score_exact`
и `base_score_exact`.

### Как убедиться, что числа верные

Три независимых способа, от самого быстрого к самому строгому.

**1. Клик по ячейке тепловой карты.** Любое число раскрывается в слагаемые: сколько было, какая мера сколько
дала (с показом «эффект × доля из-за лага»), был ли бонус синергии, обрезала ли шкала результат. Например,
B1 в Нуре: `55.00 + 10.50 (M10: +12 × 0.875) + 2.00 (синергия M10+M12) = 67.50`.

**2. Тесты.** `make test` — 24 теста: контрольные числа датасета, все восемь правил валидатора, аддитивность
Шепли, санитайзер произвольного события и проверка того, что советник не может протащить выдуманный Score.

**3. Независимая перепроверка.** `make verify` запускает `tools/selfcheck.py`, где формула и правила
реализованы **заново, без единого импорта из `app.engine`**, после чего результаты сравниваются построчно:

```
проверка                                              независимо          движок
База без решений                                       52.557680       52.557680  ✓
Пример из датасета                                     56.543070       56.543070  ✓
Сумма вкладов по Шепли = прирост                        3.985390        3.985390  ✓
Показанная дельта = score − база                        3.980000        3.980000  ✓
Число допустимых наборов                                  694395          694395  ✓
Глобальный максимум                                    57.236735       57.236735  ✓
```

Полный перебор занимает около 10 секунд на чистом Python. Совпадение по **числу допустимых наборов** —
самая ценная строка: оно сходится, только если обе реализации одинаково поняли все восемь правил.

## API

|---|---|---|
| GET | `/api/meta` | датасет, правила, события, статус LLM |

| GET/POST | `/api/leaderboard` | лидерборд / отправка сценария |

## Дизайн

Интерфейс собран по `DESIGN.md` — это файл дизайн-системы **stripe** из коллекции
[voltagent/awesome-design-md](https://github.com/voltagent/awesome-design-md), скопированный без правок, плюс
приложение с правилами проекта. Светлые поверхности, разделение **тенью, а не обводкой**, индиго #533afd,
который никогда не несёт данных — только «сюда можно нажать».

Первая версия была собрана по `linear.app` и не сработала: ступени его лестницы поверхностей различаются на
1.5–2% светлоты, поэтому слои не читались и единственным разделителем осталась линия — на одном экране вышло
**108 обведённых элементов из 337**. После переезда на stripe рамок осталось **11**, и все у полей ввода и
вторичных кнопок. Разбор этой ошибки — в приложении к `DESIGN.md`.

Палитра направлений пересобрана под белый фон и провалидирована: смежная CVD-разделимость ΔE 16.3 (цель ≥8),
порог нормального зрения ΔE 19.6 (порог ≥15). Три оттенка дают меньше 3:1 — это разрешённое послабление,
но оно обязывает всегда ставить рядом со свотчем подпись.

Навигация вынесена в боковую панель: каждый шаг подписан словами и показывает, почему он пока закрыт.
При первом входе запускается пошаговый тур с подсветкой элементов, вернуть его можно кнопкой в шапке.
Рядом с сырым Score показывается прогресс к максимуму — весь достижимый диапазон всего около пяти баллов
(52.04 у худшего допустимого плана, 57.24 у лучшего), и проценты читаются гораздо лучше абсолютного числа.

Термины движка (Score, лаг, критическая ячейка, вклад по Шепли, перцентиль, Парето, синергия) раскрываются
подсказкой по наведению. Коды показателей T1…C2 расшифровываются там, где по ним принимают решение: подсказкой
на каждом чипе эффекта и сворачиваемой легендой в каталоге. На экране результата главное вынесено наверх —
оценка, фраза-вывод обычным языком и «до/после»; вклад мер и таблица 5×10 живут под кнопкой «Подробности
расчёта» (на широком экране развёрнуты сразу).

## Деплой

### Что нужно знать до того, как платить за железо

**Приложению не нужен GPU.** Тяжелее всего здесь полный перебор 694 395 наборов — он занимает
**0.3 секунды на обычном CPU** и кешируется. Всё остальное — FastAPI и статика. Арендовать GPU-инстанс
ради хостинга этого приложения нет смысла.

GPU нужен только в одном случае: если вы хотите **сами поднять модель** (vLLM) вместо обращения к чужому API.
Это осознанный выбор ради истории «мы крутим свою модель», а не техническая необходимость.

### Вариант A — один CPU-сервер, всё в одном месте (рекомендуется)

FastAPI сам раздаёт собранный фронтенд, поэтому нужен один процесс и один порт. Никакого CORS, один адрес.

```bash
git clone <repo> && cd hack-.../akim-sim
cp .env.example .env && nano .env      # ключ LLM
docker compose up -d --build           # → порт 8000
```

Подойдёт самый дешёвый VPS. Лидерборд лежит в SQLite на volume `akim-data`.

### Вариант B — фронтенд на Netlify, бэкенд отдельно

Netlify раздаёт только статику. Перенести туда бэкенд целиком не получится, и дело не только в языке
(функции Netlify пишутся на JS/TS и Go, Python в документации не заявлен) — сама форма не подходит:

- лидерборд живёт в SQLite, которому нужен постоянный диск;
- оракул перебирает 694 395 наборов и держит результат в памяти процесса — на холодном старте
  бессерверной функции это пришлось бы делать заново при каждом запросе;
- обращения к LLM у Советника идут агентным циклом до шести шагов и не укладываются в типичные лимиты.

Поэтому бэкенд всё равно живёт на сервере, а Netlify берёт на себя фронт:

1. В настройках сайта задайте переменную сборки **`VITE_API_BASE`** — адрес бэкенда,
   например `https://akim-api.example.com`. Конфиг сборки уже лежит в `frontend/netlify.toml`.
2. Бэкенд поднимите как в варианте A. CORS уже открыт (`allow_origins=["*"]`).

Без `VITE_API_BASE` фронт ходит по относительным путям — это режим «всё на одном сервере».

### Вариант C — своя модель на GPU

Если нужен именно свой инференс: поднимите vLLM на GPU-инстансе и укажите в `.env`

```bash
LLM_PROVIDER=custom  LLM_BASE_URL=http://127.0.0.1:5000/v1  LLM_MODEL=<имя>  LLM_API_KEY=null
```

Для Советника серверу vLLM нужны `--enable-auto-tool-choice` и подходящий `--tool-call-parser`,
иначе этот агент уйдёт в шаблонный режим (остальные три и движок продолжат работать).

## Потенциал развития

- Подключение реальных открытых данных Астаны вместо синтетики (структура `data/*.json` уже под это готова).
- Многопользовательский режим в реальном времени и турнир команд по серии событий.
- Обучение весов и эффектов мер на исторических данных; калибровка лагов.
- Расширение агентов: «эксперт по закупкам» с оценкой реализуемости, генерация дорожной карты по кварталам.
